> 生成：2026-08-19。状态标记：✅ 已落地 · ⚠️ 部分/骨架/假数据 · ❌ 未做。

> **⚠️ 2026-08-19 晚 · v4 突破更新（本表下半部分状态已被推翻）**

## 1.5 v4 突破记录（2026-08-19 晚，A 轨道翻盘）

> 这段是原表**缺失**的、但比上面所有模块都重要的三件事。检测主链就是从这三步起死回生的。

### 1.5.1 83% 泄漏（最致命，全局坑库第 1 条必须补这个实锤）

- 用 **sha256** 实测（不是文件名匹配）：旧 v3 的 train/val 内容撞了 **2071 个唯一内容**，即 **83% 的 val 图在 train 里出现过**；
- 文件名匹配会漏，因为 val 文件名被加了类名前缀（`erosion_`/`protective_film_damage_`/`localized_damage_`/`coating_detachment_`），把 base 名改了；
- **后果**：旧 v3 的 mAP50=0.58 是开卷考试，废数，任何论文结论都不能引用它。

### 1.5.2 原生高清（小目标根因）

- 之前 A4 把「小目标漏检」归因于需要 SAHI/超分，**方向错了**；
- 真实根因：ILIAD/WTBs2025 都被 Roboflow 压到 640，缺陷只剩 ~10px（伪小目标）；
- 正解：**DTU 原图 5280×2970**（Mendeley `hd96prn3nc`，`imadgohar/DTU-annotations` 标注），切成 1024 瓦片后缺陷保住**原生 ~24px**；
- 反推切片约定：`DJI_XXXX_R_C.JPG` = 原图 `[C×1024:(C+1)×1024, R×1024:(R+1)×1024]`，纯偏移无缩放，stride=1024，5×2 网格（只覆盖左上 5120×2048，底部 922px 未标）。

### 1.5.3 clean 核实（负样本不是"没做"，是"没核实"）

- 负样本**早就做了**（v2 469 张、v4_quick 2453 张 clean 空 txt）——原表 A1 写"负样本完全没动"是错的；
- 真正的坑是「未标注图 ≠ clean」：Kimi 视觉筛查 40 张未标注图，**45% 其实有缺陷**；
- 修正：`clean_binary_v4_quick` 只保留「作者标注图内的无缺陷区域」2453 张 clean，丢弃 2550 张不可靠 clean。

### 1.5.4 最终结果（当前唯一可信数字）

| 指标 | v2(640 小目标) | v4(yolo11s@1024) |
|---|---|---|
| mAP50 | 0.24 | **0.674** |
| mAP50-95 | 0.106 | **0.348** |
| Precision | 0.394 | **0.795** |
| Recall | 0.29 | **0.664** |

- 数据：`datasets/derived/clean_binary_v4_quick/`（587 defect + 2453 clean = 3040 张 1024 瓦片，零 parent 泄漏）；
- 权重：`v4/weights/best.pt`（yolo11s，epoch 182 按 mAP50-95 选）；
- **剩余真缺口**：defect 只有 423 张训练图，是 mAP 天花板；想再涨唯一的路是加 defect 数据（把 Kimi 筛出的假 clean 重新标注缺陷）。

## 2. 逐模块：实锤缺口 + 预测的乱子 + 方案 + 数据

### A1 二分类重打标签与类别平衡 —— ⚠️ P0/A

**已经做了（实锤）：**
- `research/专项/A1/remap_to_binary.py` 已跑通：22394 → 22394 框，0 错误。多类（腐蚀/裂纹/前缘）→ 二分类 `defect` 的映射本身没问题。

**没做/有问题（实锤）：**
1. `train_cli.py --cls_pw` 是**死参数**：argparse 解析了但没接进 `model.train()`；且 ultralytics 根本没有 `cls_pw` 这个参数（类别权重按频率自动算，focal 用 `fl_gamma`）。"加权/focal 对照已备好"不成立。
2. **负样本策略完全没动**（A1-01 要求人工确认无缺陷图当负样本）——二分类检测没有负样本是硬伤，会误报爆表。
3. **`annotation_guideline_v1.md`（双人复标指南）没写**（A1-02）。
4. **`group_split` 是近似分组**：按文件名前缀分了 9 组，没有真 `blade_id/flight_id` 元数据，"锁定 test 集"比文档理想弱。
5. **`data_sources.csv` + 完整 `manifest.csv` 没建**：两处路径都是 False，ILIAD 的许可证/版本/下载哈希没记录，违反数据纪律。

**预测会出的乱子：**
- 误报率虚高（无负样本，模型对 clean 图没约束）。
- 假 clean 混入负样本（→ 把真实缺陷图当"干净"教模型，压 Recall）。
- 近似分组的 test 集里混进 train 的近重复帧（→ 时间泄漏，指标虚高）。
- 复标口径不一致（→ 标注噪声，AP 上不去还找不出原因）。

**方案（按顺序）：**
1. `train_cli.py` 去掉 `--cls_pw`，改成 ultralytics 认可的 `fl_gamma` 或自定义 `class_weights` 字典（一行 wiring）。
2. 负样本：从 DTU Nordtank / Roboflow Universe 拉 clean 叶片图，**人工逐张确认**再进集（见 §4）。
3. 写 `annotation_guideline_v1.md`：缺陷边界定义 + 双人双盲复标 + 一致性 kappa 门槛。
4. 补 `data_sources.csv`（许可证/SHA/版本/下载日期）+ 完整 `manifest.csv`（image/split/sha256/group_id）。

**数据去哪找：** 见 §4 表 A1 行。

### A2 模型选型与尺寸分层 —— ❌ P0/A

**已经做了：** 只有基线（YOLOv8n，mAP50≈0.58，且是**早期泄漏版本**，不可信）。

**没做：** n/s/m × 640/1280 消融，AP_S/M/L 尺寸分层，时延对比。单卡 ≥12GB（Colab 免费版不够，要 Pro 或 AutoDL/租卡）。

**预测会出的乱子：**
- **模型名混乱**：这个项目里 YOLOv8 和 YOLO11 混着用（v4 权重实际是 `yolo11s.pt`），论文方法节写错架构是硬伤。
- 尺寸分层不做 → 小目标 AP_S 塌掉，和 A4 纠缠不清。
- 只报一个 mAP → 看不出缺陷尺寸敏感度。

**方案：** 固定种子 seed=0，`n/s/m × {640,1280}` 六组，每组报 mAP50 / mAP50-95 / AP_S / AP_M / AP_L / 时延 / 参数量。

### A3 雾天/盐雾感知 —— ⚠️ P1/A

**已经做了：** `clean_and_visibility.py` 存在（大气散射/Koschmieder 模型）。

**没做/有问题（实锤）：**
1. **只跑了 200 张**：脚本硬编码 `imgs[:200]`，全量 13k 雾配对没做。
2. `consistency_train.py` / `dehaze_joint.py` **是接口骨架**：只有 `build_model/loss/train_step`，缺 dataloader、完整训练循环、ultralytics 集成——传 GPU 也跑不起来。

**预测会出的乱子：**
- **合成雾 ≠ 真雾**（分布偏移）：模型在仿真雾上学的东西，到真实海雾/盐雾上掉点，论文里被 reviewer 抓"没真雾证据"。
- 特征一致性 vs 任务驱动去雾二选一没定，两条路都做了一半。
- 骨架当就绪（同上）。

**方案：** ① 去掉 200 限制跑全量（先确认磁盘）；② 明确选一条路（建议：特征一致性为主、去雾为辅），补全训练循环；③ 用真实雾数据集做跨域验证。

**数据去哪找：** §4 表 A3 行（RESIDE / O-HAZE / Foggy Cityscapes / RTTS / RTTF）。

### A4 小目标增强 —— ⚠️ P2/A

**已经做了：** `copy_paste_aug.py`（采样函数）、`fault_inject_comm.py`（状态机类）、`sahi_slice.py`（框架）都存在。

**没做/有问题（实锤）：**
1. `copy_paste_aug.py` 是采样函数，**没接进 Dataset**。
2. `fault_inject_comm.py` 是状态机定义，**没跑注入矩阵**（要求 N≥20/格）。
3. `sahi_slice.py` 要 `best.onnx`（现在只有 `.pt`）。

**预测会出的乱子：**
- 小目标漏检（缺陷只占图极小面积，基线 Recall 低）。
- Copy-Paste 贴得太假 → 过拟合粘贴纹理。
- SAHI 时延爆炸 → 实时性崩，论文"实时检测"站不住。

**方案：** ① 先 ONNX 导出 best.pt；② Copy-Paste 接进 Dataset（限缺陷类，控制粘贴数量）；③ 超分（Real-ESRGAN）放最后当兜底。

### B1 EKF 抗风实测 —— ❌ P1/B

**已经做了：** `ekf_ablation.py` 存在，但**结果偏弱**——简化成 1 轴线性 CA 模型，三档 Q/R 的 RMSE 几乎一样（0.798/0.799/0.800），自适应 Q 优势根本没体现。

**没做：** 真实风场实测（风扇+风速仪+固定相机+棋盘格）。

**预测会出的乱子（重灾区）：**
- **把"风扇档位"当风速**：没有风速仪 = 没有风况真值，消融相关性是假的。
- Tello 0.531→0.062m 的**原始遥测不在仓库**（只有仿真日志，没有 WSY5/WSY6 室外实测 CSV）→ 数字对但**无法复现**。
- 模型太简化 → 消融"没出效果"，论文里自证不了。

**方案：** 先补原始遥测入库；实测时必须风速仪给真值；ekf 模型升级（别用 1 轴线性 CA）。

## 3. 全局「乱七八糟问题」库（跨模块，逐条对照）

这 8 个是任何模块都会翻车的坑，写到哪个模块都要回头查一遍：

| # | 坑 | 检测方法 | 缓解方案 |
|---|---|---|---|
| 1 | **指标虚高**（时间泄漏/重复帧跨 split） | sha256 + 按 flight/家族分组重切，查跨 split 组数 | 分组切分（GroupKFold），断 0 跨 split |
| 2 | **骨架当就绪**（`build_model` ≠ 能跑） | 看有没有 dataloader + 训练循环 + 集成 | 补全后标「✅ 跑通」，否则标「⚠️ 骨架」 |
| 3 | **假数据当真值**（`np.random.normal` / 风扇档位当风速） | grep `np.random` / `rng.normal` | 必须实物实测，模拟量只能当占位 |
| 4 | **分布偏移**（合成雾≠真雾） | 用真实雾集做跨域验证 | 混合合成+真实训练，报告跨域掉点 |
| 5 | **过拟合信号**（train/val 差距大、小数据集记忆） | 看 val 曲线是否早停、train/val 剪刀差 | 加正则/早停/更多数据 |
| 6 | **评估偏差**（只看 mAP50） | 单指标 | 报 mAP50 + mAP50-95 + AP_S/M/L + FP |
| 7 | **命名/版本混乱**（YOLOv8/YOLO11、Blade30/ILIAD 混用） | 查 args.yaml 的 `model:` | 统一用实际 `yolo11s.pt`，论文写 YOLO11s |
| 8 | **数据纪律缺失**（无 manifest/许可证/SHA） | 查 data_sources.csv 是否存在 | 补全，守 README 纪律 |

### 4.2 合成雾（找不到真雾时的兜底，大气散射模型）

```
I(x) = J(x)·t(x) + A·(1 − t(x))
t(x) = exp(−β·d(x))     # β 散射系数，d 景深
```
参数：β ∈ [0.5, 2.0]（雾由轻到浓），A 大气光 ∈ [0.7, 1.0]，d 用均匀/随景深变化。合成模糊核（D1）用运动 PSF（长度 L、角度 θ）。
