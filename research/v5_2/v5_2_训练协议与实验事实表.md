## 一、v5.2 第一次基础实验(写死,不换任何变量)

### 1.1 固定配置(单变量原则)

| 项 | 值 | 说明 |
|---|---|---|
| 模型 | `yolo11s.pt`(官方预训练) | 不从 v4/v5 best.pt 续训 |
| 输入尺寸 | 1024 | 不变 |
| 批次 | 8 | 不变 |
| 采样 | 保留 v5.1 正样本重复采样(负/正 ≈ 2:1) | 已证明有效 |
| 增强 | 保留 v5.1 弱 Mosaic(mosaic=0.2, scale=0.25, translate=0.05) | 已证明有效 |
| epochs | 40~60 短程门槛 | **不跑 200** |
| seed | 至少 `0` 和 `1` | 防单 seed 偶然尖峰 |
| 训练期验证 | **只用 ID validation** | 选 best.pt + 早停 |
| 最终评估 | ID validation + OOD test | OOD 只测一次 |

> **禁止同时换**:YOLO11m、输入尺寸、损失函数、增强策略。任何结果变化都必须能归因到单一因素。

### 1.2 停止标准(提前写进脚本)

| 触发条件 | 动作 |
|---|---|
| 第 40 轮 ID Recall 仍接近 0 | 停止 |
| 第 50~60 轮 ID mAP 无持续改善 | 停止 |
| train loss 继续降、ID val loss 持续升 | 停止(过拟合) |
| OOD Recall 接近 0 | 记录为「跨场景失败」,不继续堆 epoch |

### 1.3 评估口径(三集合职责,不混用)

| 集合 | 职责 | 可复用次数 |
|---|---|---|
| **ID validation** | 选 best.pt、调阈值/采样/增强、早停 | 训练期每轮 |
| **OOD test** | 最终跨场景泛化,唯一报告成绩 | **只测 1 次**(模型方案锁定后) |
| **review** | 存异常框/语义不确定图 | 不进正式指标,直到人工复核完成 |

### 1.4 基础实验要回答的唯一问题

> **在标签与验证协议修正后,基础模型(YOLO11s)能否正常学习并跨场景迁移?**

不追求最高分。只有 `YOLO11s` 在 ID validation 稳定、且 OOD Recall 不再近零后,才比较 YOLO11m、加复杂增强、或做 A3 抗雾训练。

## 二、实验事实表(v4 / v5 / v5.1 —— 口径分开,不下结论)

| 版本 | 划分方式 | 主要评估含义 | 是否适合当最终性能 |
|---|---|---|---|
| **v4** | 按采集单元分组(拦内容级泄漏) | 含较多**相邻场景相似性**的评估;分数虚高 | **否**(有相邻帧垫高) |
| **v5** | 连续场景块整体隔离 | **场景隔离后的 OOD 压力测试**;能暴露跨场景短板,但 val 单场景占 81% 框、噪声极大 | **否**(验证集过度偏置) |
| **v5.1** | 同 v5,加正样本重采样 + 弱增强 | 证明 Recall 改善(+175%)、mAP 翻倍(+99%),但仍未达可用 | **否**(阶段性修证) |
| **v5.2** | ID validation + OOD test + review 三分 | 计划中的正式协议 | **是**(后续正式口径) |

> **三个数字不得放进同一张「模型性能对比表」直接比较**(验证条件不同):
> - v4 best ep182 = mAP50 **0.6679**(有相邻帧相似垫高);
> - v5 best ep68 = mAP50 **0.0266**(单场景压爆的极端 OOD);
> - v5.1 best ep50 = mAP50 **0.0531**(修采样后仍受域偏移限制)。
> 最多放在「数据划分演进与失败诊断」里解释,不能当并列的性能数字。

### 2.1 当前论文可记录的唯一结论句(不下最终结论)

> v5.1 的正样本重采样和弱增强能够改善低召回问题,但模型仍受到场景域偏移和部分验证标签几何异常的限制,因此尚不能据此确定最终跨场景泛化性能。

## 五、待办与依赖(诚实声明)

1. **23 特殊框复核**:v5 划分的 23 框(DJI_0234–0251)原始数据在 **ClawsGO 侧**,本机 v4_quick 里没有该 val 划分;拿到他的 manifest 后 audit 脚本会自动置标 ClawsGO priority。本机当前的 `review_manifest.csv` 覆盖的是 v4_quick 里同类几何异常框(touch_boundary/细长/小目标),可作为**同一套复核流程的预演**。
2. **pHash 近重复**:本机缺 `imagehash`,第 04 项已降级为 sha256。要启用 pHash,`pip install imagehash pillow` 后重跑即可(脚本自动探测)。
3. **9 个越界残框**:preflight 第 08 项硬失败,正是 audit 判为 `invalid` 的 9 框(坐标越 [0,1])。进 GPU 前必须先人工处置(修正或剔除),否则污染训练。
4. **B2 真实平台参数 / B1 风场实测 / C1 台架 / D2 实机时延**:仍缺硬件,与本次数据协议无依赖,现状见 `GAP_TRACKER.md`。
