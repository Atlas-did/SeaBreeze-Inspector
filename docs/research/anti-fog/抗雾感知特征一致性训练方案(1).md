# 抗雾感知模型 · 特征一致性训练详细方案

> 目标:让无人机感知网络在「雾 / 盐雾杂质 / 传感器噪声 / 运动模糊 / 小目标」下,提取与晴空
> **一致**的特征,进而输出一致的位姿/控制量或检测结果。不依赖 ComfyUI,纯 PyTorch 实现,
> 可与现有 YOLOv8 流水线衔接。

---

## 0. 一句话核心思想

> 不学「怎么把雾擦掉」(去雾),而学「不管有没有雾,我都提取出相同的飞行环境信息」(特征一致性)。
> 若还能拿到飞控状态(roll/pitch/yaw/x/y/z 或速度指令),则进一步让网络直接预测控制量并保持
> 有雾/无雾输出一致——即**面向控制的抗雾感知模型**。

---

## 1. 为什么「特征一致性」优于「去雾」

| 维度 | 像素级去雾(dehaze) | 特征一致性(本方案) |
|---|---|---|
| 学习目标 | $I_{clean}=G(I_{fog})$,逐像素还原 | $z_{fog}\approx z_{clean}$,特征对齐 |
| 需要配对 GT 图 | 是(且要求像素级对齐) | 配对是「构造出来的」,天然免费 |
| 泛化 | 过平滑、易产生伪影、雾浓度外推差 | 只约束表征,不同雾浓度都往同一特征靠 |
| 与任务对齐 | 间接(先去雾再检测/控制) | 直接(损失直接作用在任务输出上) |
| 对无人机稳定性 | 去雾引入额外延迟与不确定性 | 特征不变 = 控制量不变 = 稳定 |

核心洞察(你说的那点):**配对数据不需要真实拍摄**。因为我们「在干净图上加雾」,天然得到
$(\text{无雾},\ \text{有雾})$ 一一配对,这比任何公开去雾数据集都好——视角、时刻、内容完全一致。

## 2. 数学形式化(把你写的思路严格化)

### 2.1 符号
- $I_e$:无雾(干净)图; $I_f$:有雾图(由 $I_e$ 合成)。
- $E(\cdot)$:编码器(backbone), $z_e=E(I_e)$, $z_f=E(I_f)$。
- $F(\cdot)$:任务头(检测头 或 位姿/控制回归头), $p_e=F(z_e)$, $p_f=F(z_f)$。
- $p^*$:真实监督(位姿 $[x,y,z,roll,pitch,yaw]$ 或控制量 $[u_x,u_y,u_z]$)。

### 2.2 三路损失

**(a) 任务损失(有真值监督时)**
$$
\mathcal{L}_{state} = \| p_e - p^* \|_2^2 \quad(\text{位姿/控制回归})
$$
检测任务则替换为 YOLO 的分类 + 回归损失。

**(b) 输出一致性损失(核心)**
$$
\mathcal{L}_{cons} = \| F(I_f) - F(I_e) \|_1 \quad \text{或} \quad \| p_f - p_e \|_2
$$
这是最稳的一路:直接约束「有雾和无雾,任务输出一致」。

**(c) 特征一致性损失**
$$
\mathcal{L}_{feat} = \| \mathrm{proj}(z_f) - \mathrm{proj}(z_e) \|_1
$$

**总损失**
$$
\mathcal{L} = \lambda_1\mathcal{L}_{state} + \lambda_2\mathcal{L}_{cons} + \lambda_3\mathcal{L}_{feat}
$$

### 2.3 三个工程修正(避免踩坑)

1. **特征别直接对齐原始 encoder 输出**:原始特征维度高、方差分布不均,直接 L1 容易被高方差维
   主导甚至塌缩。加一个 2 层 MLP **投影头** `proj(·)`,输出 128 或 256 维,再 L1。可进一步用
   **余弦相似度**替代 L1(等价于对特征做归一化)。
2. **一致性优先约束「输出」而非「特征」**:$\mathcal{L}_{cons}$ 比 $\mathcal{L}_{feat}$ 更直接、
   更稳,权重应 $\lambda_2 \ge \lambda_3$。
3. **无真值时的退化方案**:若拿不到飞控状态真值,就把 $F$ 设为一个「自监督代理任务」——例如
   预测图像的**雾浓度参数 $\beta$ 或大气光 $A$**,并要求 $F(I_f)\to(\beta,A)$ 与 $F(I_e)\to(0,1)$
   一致;或者直接用 SimCLR 式对比损失在配对图上做表征对齐。

## 3. 配对数据生成方案(最核心、成本最低)

### 3.1 雾合成 —— 大气散射模型(Koschmieder / ASM)

$$
I(x) = J(x)\cdot t(x) + A\bigl(1-t(x)\bigr),\qquad t(x)=\exp(-\beta\,d(x))
$$
- $J$:干净图;$A$:大气光(海雾取灰白,如 $(0.7,0.75,0.8)$);$\beta$:散射系数(雾浓度);
  $d(x)$:逐像素深度。
- **无深度图时**:用均匀雾 $t=\text{const}$,或从高斯/斜面合成一张伪深度图做空间渐变雾。
- **多浓度**:$\beta\in\{0.5,1.0,1.5,2.0\}$ 对应薄雾→浓雾,生成「不同浓度」曲线用。

```python
def add_fog(img, A=(0.75,0.78,0.8), beta=1.0, depth=None):
    h, w = img.shape[:2]
    if depth is None:                      # 均匀雾
        t = np.exp(-beta * 0.5)
    else:                                   # 渐变雾
        t = np.exp(-beta * depth)
    t = np.clip(t, 0.05, 1.0)[..., None]
    return (img.astype(np.float32) * t + np.array(A) * (1 - t)).astype(np.uint8)
```

### 3.2 杂质 / 噪声合成(盐雾、传感器噪声、运动模糊、雨滴)

| 干扰 | 模型 | 配对方式 |
|---|---|---|
| 盐雾颗粒 | 随机白色小斑点 + 高斯模糊(模拟镜头盐晶) | 干净图 → 加颗粒 |
| 传感器噪声 | 高斯噪声 / 泊松噪声 | 干净图 → 加噪声 |
| 运动模糊 | 线性运动核(长度按晃动等级) | 干净图 → 卷积核 |
| 雨滴/水渍 | 半透明圆斑贴片 | 干净图 → 叠加 |
| 低对比度 | gamma 变换 / 直方图压缩 | 干净图 → 变换 |

**关键**:每张干净图可以「随机组合」多种干扰,得到 $I_f$,配对关系天然成立。

### 3.3 小目标处理(与抗雾正交、需单独解决)

特征一致性解决「雾不变」,**不解决小目标**(那是分辨率/容量问题)。两者叠加:
1. **超分放大**:对缺陷小区域 2×/4× 超分(Real-ESRGAN / SR 模型)后送检测;
2. **SAHI 切片推理**:大图切 512×512 重叠块检测再合并;
3. **训练侧 copy-paste**:把小缺陷目标粘贴到多张背景图,增加小目标正样本密度;
4. **尺度分层评测**:AP_S/M/L 分报,量化小目标提升。

## 4. 网络架构(两个方案)

### 4.1 方案 A:面向控制的抗雾感知模型(回归)

```
                    ┌─ clean: I_e ─┐
共享权重 E(ResNet18) ┤               ├→ 投影头 → z (128维)
                    └─ fog:   I_f ─┘
         z ─→ 控制头 F(3层MLP) ─→ p̂ = [x,y,z,roll,pitch,yaw] (或 [u_x,u_y,u_z])
```
- 推理时**只走有雾那一路**(实际飞行输入就是有雾/有噪声的图),学到的 $F$ 对雾不敏感。
- 适合:直接输出位姿/速度指令,与 Tello 的 vgx/vgy/姿态对齐。

### 4.2 方案 B:雾不变检测模型(推荐,直接接你们的 YOLO)

把方案 A 的 $E$ 换成 **YOLOv8 backbone**(或保留 ultralytics 框架,加一个辅助一致性分支):
```
YOLOv8 backbone ─┬─ 检测头(正常输出框+类别)
                 └─ 投影头 → z  (新增,仅训练时用)
```
- 训练时每个 batch 同时喂 (clean, fog) 对,检测损失照常,**额外加 $\mathcal{L}_{feat}$ 约束 backbone 特征雾不变**;
- 推理时完全无额外开销(投影头丢弃),检测流程不变。
- 这是「把抗雾能力内化进检测器」的最小改动方案。

## 5. 损失函数完整定义

```python
# 回归版(方案A)
L_state = mse(p_clean, p_gt) + mse(p_fog, p_gt)      # 有真值时
L_cons  = F.l1_loss(p_fog, p_clean)                  # 输出一致
L_feat  = F.l1_loss(proj(z_fog), proj(z_clean))      # 特征一致(投影后)
loss    = 1.0*L_state + 0.5*L_cons + 0.1*L_feat

# 检测版(方案B)
loss = L_yolo(clean) + L_yolo(fog) + 0.1*L_feat(backbone特征)
```
- 无真值版本:去掉 L_state,提高 L_cons 权重至 1.0。
- $\lambda$ 建议:$\lambda_1=1.0,\ \lambda_2=0.5,\ \lambda_3=0.1$;训练后期可把 $\lambda_3$ 退火到 0(特征一致性前期引导、后期让位任务损失)。

---

## 6. 训练协议

1. **Stage 1(表征对齐)**:冻结任务头,只训 backbone + 投影头,$\mathcal{L}_{feat}+\mathcal{L}_{cons}$,10–20 epoch;
2. **Stage 2(联合微调)**:解冻全部,加 $\mathcal{L}_{state}/\mathcal{L}_{yolo}$,$\lambda_3$ 退火;
3. **超参**:AdamW lr=1e-3(backbone 1e-4),batch 16,输入 640(检测)/224(回归),GPU 单卡即可;
4. **数据配比**:每个 batch 内 clean:fog = 1:1,同一 clean 的 fog 变体在同 batch 内成对。

## 7. 评估指标

| 指标 | 定义 | 说明 |
|---|---|---|
| 雾鲁棒性曲线 | 各 β 浓度下的 mAP / 位姿误差 | 替代「精度下降」的模糊说法 |
| 特征一致性分数 | $\|z_f - z_e\|$ 训练前后对比 | 验证表征是否真的对齐了 |
| 控制误差 | 位姿 RMSE / 控制量 RMSE | 方案 A 直接看飞行稳定性 |
| AP_S/M/L | 分尺度 mAP | 量化小目标提升 |
| 消融 | 加/不加 $\mathcal{L}_{feat}$、加/不加去雾预处理 | 证明一致性损失的价值 |

## 10. 风险与备选

| 风险 | 缓解 |
|---|---|
| 真实海雾 ≠ 合成雾(分布差异) | 用 β 多档 + 空间渐变雾逼近;后续补 1–2 次真实海雾图微调 |
| 特征一致性导致表征塌缩 | 投影头 + 余弦距离 + batch 内负样本(SimCLR 化) |
| 小目标仍差 | 特征一致性不解决小目标,必须叠加 §3.3 的超分/切片/copy-paste |
| 无飞控真值 | 退化为自监督(§2.3 第 3 条)或只做检测版(方案 B) |

## 11. 数据加权与类别平衡 —— "复制图片提分"现象的科学化

### 11.1 你发现的现象是对的,但它是三个不同问题的叠加

| # | 真问题 | 你的朴素观察 | 正确工具 |
|---|---|---|---|
| 1 | **类别不平衡**(3 类缺陷样本数不均) | "复制少数类图片两倍" | 类别权重 / oversampling / focal loss |
| 2 | **样本质量差异**(有的图清晰标注准,有的脏) | "好图多训练几次" | 样本重加权 / hard example mining / 数据清洗 |
| 3 | **小目标**(56.8% 框 <0.1% 面积) | (复制整图无效) | copy-paste / ATFL / 切片 / 超分 / P2 头 |

### 11.2 "复制图片两倍"的真相

复制一张图两次 = 把它的 loss 权重 $\times2$,是 **oversampling 的最粗糙形式**(等效于该样本在
batch 内出现概率翻倍)。它有效,但有三条边界:
1. **不增加信息**:重复图 $\neq$ 新数据,不提升该类的泛化,只会让模型对那几张图更熟;
2. **救不了小目标**:整图复制后,里面的小目标在整图里还是小;
3. **过度重复会过拟合**:少数类被反复记背,验证集上掉点。

**结论:你摸到了"样本加权"的门,但正确做法是把它从"复制图片"升级为"损失函数里的权重"。**

### 11.3 冲 95% 的现实配方(权重只是其中一环)

| 杠杆 | 方法 | 预期增益 | 依据 |
|---|---|---|---|
| 类别平衡 | 类别权重 / focal loss(γ=2) | mAP50 +0.05~0.10 | 类别不平衡是标准问题,加权是标准解 |
| 小目标 | **ATFL(自适应阈值焦点损失)** / copy-paste / 切片 | +0.05~0.10 | ATFL 专治小目标(见 [YOLOv11 小目标改进](https://developer.aliyun.com/article/1651326)) |
| 数据质量 | 删"小猪佩奇"等脏样本 + 标签清洗 | +0.03~0.05 | 脏标签直接拉低上限 |
| 模型容量 | YOLOv8n → v8s/m | +0.05~0.08 | nano 容量是小目标瓶颈 |
| 输入分辨率 | 640 → 1280 保持 | 已计入 | V3 已用 1280 |
| **合计(现实)** | 0.58 起步 | **≈0.75~0.85** | 权重是必要非充分条件 |

**诚实判断**:权重/focal loss 是"0.58→0.72"的杠杆,不是"0.58→0.95"的魔法。**95% 需要
二分类任务重定义 + 干净标签 + 更强模型 + 小目标专项 + 足够数据**,五件事一起做,缺一不可。


### 11.5 为什么这些都不需要"大模型"

类别权重、focal loss、ATFL、hard example mining、copy-paste **全部是小模型训练技术**,在
ultralytics 里一行就开,推理仍是 3.2MB 的 YOLOv8。**大模型只用在三个外围**:①生成式模型(SD/FLUX)
合成海雾/缺陷数据扩充;②DINOv2/CLIP 预训练权重蒸馏给小 backbone;③SAM 辅助二分类标注。训练本身
的"权重"这件事,小模型自己就能搞定。
