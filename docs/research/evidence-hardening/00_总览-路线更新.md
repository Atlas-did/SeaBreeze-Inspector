## 1. 新优先级:三层倒排(替代原 plan 的 Phase 0-3)

```
第一层 · pipeline 稳定(你现在说的"先跑通")       ← 最高优先,不依赖论文
    A2 train_cli 干净可复现      → 多轮训练(11s/8s, binary/multi)才有意义
    B1 EKF 消融改造              → 自适应 Q 卖点才有实验支撑
    B2 抗风模型 bug 修复          → 8m/s 局限性才站得住
    C2 FK/IK 尾部修复             → 机械臂运动学结论才可辩护
    A3 数据全量化 + 基线曲线       → 雾鲁棒实验才能开始
    D2 时延实测插桩               → 闭环数字才可引用
       ↓
第二层 · 证据闭环(每个数字可复现、可溯源)
    clean_manifest 入库 + 泄漏审计
    v4/v5 训练协议 + args.yaml 回读自检
    每份报告 JSON 带 params_source / mode / seed
       ↓
第三层 · 论文从零重写(等前两层稳定)
    检测实验节:协议骨架现在定,数字最后填
    架构名/类别口径:按最终训练轮次写
    8 m/s 抗风:详细局限性讨论
    孤儿图:数字定稿后重新生成
```

**9/15 硬截止不变**。前两层如果 9/10 前稳定,论文重写仍有 5 天窗口(骨架 + 填数字)。

## 3. 论文 §5「检测实验」的策略:协议先行,数字后填

详细解释见对话正文。这里记录决策:

- **现在做**:定检测实验节的协议骨架(数据与划分、训练协议、指标、结果表、消融、局限),并补齐数据纪律(clean_manifest 入库、泄漏审计、v4/v5 manifest);

- **验收**:重写论文时,§5 检测小节是一个「留白但结构完整」的模板,10 分钟内能填完。
