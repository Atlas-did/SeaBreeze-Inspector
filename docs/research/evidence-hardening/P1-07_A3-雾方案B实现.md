# P1-07 · A3 雾方案 B 实现 —— 把「接口骨架」变成「能出消融表的真训练」

> 对应计划:`SeaBreeze_攻坚计划_v1.md` P1-7 · 证据脚本 `research/专项/A3/consistency_train.py`(主方法)+ `dehaze_joint.py`(对照基线)
> 一句话结论:**A3 的雾方案选型与方法设计已经在《抗雾感知特征一致性训练方案》文档里定稿(方案三特征一致性为本文方法、方案一/二去雾为基线),但代码只是打印了几句公式的接口骨架,没有 DataLoader、没有优化器、没有训练循环**。这一项把方案 B(雾不变检测模型)落到能跑的代码上,并在 GPU 上产出「雾浓度-精度衰减曲线 + 消融表」——这是论文「海上环境适应性」评分项里唯一有真实验证据的差异化点。

---

## 1. 结论先行

| 项 | 现状 | 改造后 |
|---|---|---|
| 代码状态 | 两个训练脚本是「接口骨架」:只定义损失函数、main 只 print | 可运行的训练脚本:Dataset + 训练循环 + 评估 + 日志 |
| 实验产出 | 无任何训练结果 | 基线衰减曲线 + 加 L_feat 的消融表 + 推理零开销证明 |
| 数据输入 | `--data-dir` 期望 A3-01 输出的 pairs.csv | 依赖 P1-10 的全量雾配对落地(两任务有依赖关系) |
| 成本 | —— | GPU(张睿服务器)+ 数据生成(先于训练) |

**为什么必须做**:攻坚方案 §六把「雾鲁棒感知」列为海上环境适应性的第一项,而论文 §4.6 已经画了「三方案对比表」——**如果只是对比表而没有实验,这个差异化点就只是设计陈述,不是证据**。评审扣分规则里「实验严谨性(P1)」明确要求「每场景至少 100 张、关键场景 1000 张,报均值±标准差,做有无三组消融」。A3 是这个评分项里唯一能出真实验的抓手。

**一个关键的成本洞察(省钱的顺序)**:雾浓度-精度衰减曲线的**「不加任何抗雾机制」基线分支,不需要新训练**——直接用已训好的 v4 检查点(ep182, mAP50=0.668)在雾合成测试集上做推理就能得到。真正的训练开销只花在「加 L_feat 的实验组」。所以实施顺序是:先免费拿到基线曲线,再投入 GPU 训练实验组。

## 2. 问题定位

### 2.1 三个脚本的现状(`research/专项/A3/`)

| 脚本 | 角色 | 现状 |
|---|---|---|
| `clean_and_visibility.py` | 数据:清晰度筛选 + 雾合成 + 可见性标记 | ✅ 可运行(纯本地),问题见 P1-10 文档 |
| `consistency_train.py` | **主方法**:特征一致性训练 | ⚠️ 骨架:定义了 `consistency_loss` / `angle_loss` / `train_step`,但 main 只有 print,无 DataLoader / 优化器 / 循环 / 评估 |
| `dehaze_joint.py` | **基线对照**:任务驱动去雾联合优化 | ⚠️ 同上,只有网络定义与损失,无训练 |

骨架代码里**方向已经正确**(与抗雾方案 §12 评审修正一致):
- 检测版只做 backbone 特征一致性,不做检测头输出一致性(`consistency_loss(z_f, z_c)`,L1,可换余弦);
- `invisible` 样本关闭检测损失(train_step 的 `visible_mask`);
- P3/P4/P5 多尺度投影头(方案 §12.2 第 6 条,代码里在 main 的 print 注释里)。

**缺的是「工程化」**:配对 Dataset、批量采样、优化器调度、训练循环、checkpoint、在雾变体测试集上的逐 β 评估、消融对比脚本。

### 2.2 方法层需要锁定的决策(方案文档里说了方向,落地要定细节)

1. **检测任务的损失**(方案 §12.1 第 2 条已修正):`L = L_yolo(clean) + L_yolo(fog)·visible_mask + λ_feat·Σ_p∈{P3,P4,P5} ||proj(z_f_p) − proj(z_c_p)||₁`,**不设** L_cons;
2. **防塌缩**(方案 §12.2 第 8 条):BYOL 式 stop-gradient + predictor,不用 InfoNCE(单卡 batch 小,负样本不够);
3. **投影头**:在 YOLO backbone 的 P3/P4/P5 各接轻量投影(1×1 conv + MLP),λ_feat 取三层之和(小目标信息在 P3,如更关心可只对 P3);
4. **训练配比**:batch 内 clean:fog = 1:1,同 clean 的 fog 变体尽量不在同一 batch(方案 §12.2 第 7 条);
5. **λ 调度**:早期 λ_feat 较大、后期退火(方案 §2.3 第 3 条改为具体 schedule,如 cosine 退火)。

### 2.3 两条实现路线(二选一,推荐路线 A)

| 路线 | 做法 | 优点 | 风险 | 工作量 |
|---|---|---|---|---|
| **A. ultralytics Trainer 子类化**(推荐) | 在 ultralytics 框架内继承 `DetectionTrainer`,重写 `get_model`/`get_dataloader`/`__call__`(或 hook 进 `loss` 处),在 YOLO 损失上**追加特征一致性损失** | 复用成熟的 YOLO 训练基建(增强/调度/指标/checkpoint),与 v4 训练协议同源,报告格式一致 | 需侵入 ultralytics 内部(`model.loss` 调用点、backbone 特征取出),版本升级会碎 | 中(0.5–1 天) |
| B. 纯 PyTorch 重写训练循环 | 自己写 Dataset + 循环 + YOLO 检测头损失 | 完全可控,无框架耦合 | 要自己实现 YOLO 损失(DFL/CIoU),容易出错且与 v4 口径不一致 | 高(2–3 天) |

**选 A 的理由**:① v4 就是 ultralytics 训的,复用同一训练协议,消融的差异只来自「有无 L_feat」这一个变量,说服力最强;② 推理路径零改动(YOLO 模型不变,只是训练时多加一个 aux 分支),天然满足「推理零额外开销」的卖点;③ 报告直接用 ultralytics 的 metrics,格式统一。**风险兜底**:把对 ultralytics 的侵入封装成 `patch_ultralytics_for_consistency.py` 一个模块,里面明确注释对应哪个版本(如 `ultralytics==8.x.y`),升级时只动这一个文件。

## 3. 实施步骤(按依赖排,分 4 个里程碑)

### Milestone 0 · 数据就绪(依赖 P1-10)
- A3-01 全量跑完,产出 `sharpness.csv` + `pairs.csv`(clean/fog 配对 + invisible_flag)。
- 划分:训练/评估用 train/val 的 clean 图及其雾变体;测试用 test 的 clean + 4 档 β 雾变体(测试集上的衰减曲线,绝不碰训练)。
- **数据纪律**:雾配对基于 clean_manifest(三向零碰撞)生成,雾变体的 sha256 同样要记录,**绝不能把同一 parent 的 clean/fog 跨 split**(否则又造出泄漏)。

### Milestone 1 · 基线衰减曲线(免费,先做)
- 用 v4 检查点 `best.pt`(ep182)在 test 的 4 档 β 雾变体上逐档 `model.val()`。
- 产出:**雾浓度-精度衰减曲线**(横轴 β=0.5/1.0/1.5/2.0,纵轴 mAP50/mAP50-95,加上 β=0 的 clean 基线点)+ 每档召回率变化。
- 这张图是「不加任何机制」的对照臂,先拿到它,训练组出来后才有对比。

### Milestone 2 · 实验组训练(需 GPU,张睿服务器)
- 按路线 A 实现 `patch_ultralytics_for_consistency.py`,在 YOLO 损失上追加 λ_feat·Σ||proj(z_f)−proj(z_c)||₁。
- 训练协议与 v4 对齐:`yolo11s`、`imgsz=1024`、`batch=8`、200 epochs、seed=0、同类增强——**保证唯一变量是 L_feat**。
- 消融组设置(评审要的三组):
  - 组 1:基线 v4(无 L_feat)——已有,直接用;
  - 组 2:加 L_feat 的雾不变训练(本文方法);
  - 组 3(可选加分):加 L_feat **并且**训练时混入雾变体(组 2 若只在 clean 上训也行,取决于时间)。

### Milestone 3 · 评估与写论文
- 在 test 雾变体上评估组 1/2,画两条衰减曲线对比 + 消融表(mAP50 逐档 β)。
- 补两个小实验:① **推理零开销证明**——对比有无投影头的推理时延(应无差异);② invisible 样本处理效果(关闭检测损失 vs 不关闭,见方案 §12.1 第 4 条)。
