## 1. 🔴 缺口一(阻塞):配对数据管线从未接入训练器

**位置**:`PairedFogDataset`(L196)+ `paired_collate_fn`(L238)定义完整,但 `ConsistencyTrainer.build`(L265-299)只重写了 `get_model` 和 `get_validator`,**没有重写 `get_dataset` / `get_dataloader`**。

**后果**:`trainer.train()` 会用 ultralytics 默认的 `build_dataset` 去解析 `--data` 传入的 yaml:
- 如果 yaml 不是标准 YOLO 格式(只有 `paired` 字段)→ **启动即崩**(check_det_dataset 找不到 train/val);
- 如果 yaml 是标准格式 → **训练照常跑,但 batch dict 里没有 `n_clean`,`_feature_consistency` 返回 None,整个训练静默退化成纯检测**——你花了 GPU 时间,得到的却是"没加 L_feat"的对照组,还以为是实验组。

**为什么冒烟没拦住**:`selftest()`(L305)手工构造 `batch = {"img", "cls", "bboxes", "batch_idx", "n_clean"}`,直接喂给 `model.loss`——**它证明的是"包装器的 forward+loss 能跑",不是"训练循环会喂配对数据"**。

**修法**(三选一,推荐 A):
- **A. 给训练器接上配对数据**:在 `_ConsistencyTrainer` 里重写 `get_dataset` 返回 `PairedFogDataset`,`get_dataloader` 用 `paired_collate_fn`。注意 `PairedFogDataset` 目前**不做 letterbox/尺寸统一**,必须补:clean 与 fog 同一场景要缩放到同一 imgsz(否则 `torch.cat` 形状对不上,模型前向也要输入是 32 的倍数);
- B. 把配对数据在磁盘上摊平成标准 YOLO 目录(clean 图 + labels 一份、fog 图 + labels 一份,`n_clean` 用 batch 前半/后半约定注入)——不侵入 dataloader,但要改 collate 契约;
- C. 最省事但弱:**放弃联合训练,只做 Stage-1 特征对齐**(纯 L_feat,无检测损失)——这需要 `loss()` 里能独立关闭检测损失,且只能得到"特征一致性"消融,得不到"检测+L_feat"的完整消融表。

### 1.1 修法 A 的骨架(可直接接进 `_ConsistencyTrainer`)

```python
def get_dataset(self, dataset, batch, mode='train', ...):
    # dataset = --data 里的 paths 或 yaml;PairedFogDataset 自己解析 pairs_csv
    return PairedFogDataset(self.pairs_csv, self.img_root, split=('train' if mode=='train' else 'val'),
                            transforms=self._build_letterbox())  # 需先补 letterbox

def get_dataloader(self, dataset, batch, mode='train', ...):
    return torch.utils.data.DataLoader(dataset, batch_size=batch, shuffle=(mode=='train'),
                                       collate_fn=paired_collate_fn, num_workers=0)
```
(注意 ultralytics 8.4.60 的 `get_dataset/get_dataloader` 签名含 `rank`/`threads` 等形参,按版本对齐。)

## 2. 🔴 缺口二(阻塞):标签从未加载

**位置**:`PairedFogDataset._load_labels`(L233-235):

```python
def _load_labels(self, clean_name):
    # 简化:标签由调用方经 --labels-dir 提供;这里返回空
    return torch.zeros((0, 5))
```

**后果**:collate 里 `clss/bboxes/batch_idx` 全部为空 → 检测损失没有监督目标 → 训练成了"纯特征对齐的无监督配对"。如果这确实是 Stage-1 的意图,应该显式做成一个开关(`--stage1`),否则与文件头声称的 `L = L_yolo(clean) + L_yolo(fog)·visible_mask + λ_feat·…` 不符。

**修法**:按 YOLO 格式读标签文件:
```python
def _load_labels(self, image_name):
    # 约定:labels/<stem>.txt,每行 "cls cx cy w h"(归一化)
    stem = os.path.splitext(image_name)[0]
    txt = os.path.join(self.labels_root, stem + '.txt')
    labs = np.loadtxt(txt, ndmin=2, delimiter=' ') if os.path.isfile(txt) else np.zeros((0, 5))
    return torch.from_numpy(labs.astype(np.float32))
```
clean 与 fog 共享同一场景标签(A3-01 的 fog 是 clean 的退化变体,框不变)。`labels_root` 从 yaml 的 `paired.labels_root` 字段传进来。

## 3. 🔴 缺口三(正确性):visible 掩码算了但没生效

**位置**:`paired_collate_fn` L261 把 `visible` 张量放进 batch,但 `ConsistencyModel.loss`(L154-161)**从未读 `batch["visible"]`**。文件头声称「invisible 样本关闭检测损失」,实际没有实现。

**后果**:一旦标签接入(缺口二),invisible(雾后目标不可见)的 fog 图仍会被强训检测损失——这正是不该做的事(雾吞掉的目标不该逼模型学)。

**修法**(最小改动,在 collate 里做):
```python
# 只对 visible=1 的 fog 样本追加标签;clean 侧始终追加
append_fog = [b["visible"] for b in batch]   # 每张 fog 图是否可训检测
# 循环里 fog 段(i+B)仅在 append_fog[i] 为真时追加该样本的框
```
这样 invisible 的 fog 图退化为「纯 L_feat 配对」,与设计一致。

## 4. 🟡 其它需要注意的(不阻塞,但上 GPU 前看一眼)

1. **loss 拼接的维度敏感**:`loss()` 里 `torch.cat([base, feat.reshape(1)])` 假设 `base` 是 ≥1 维。若 ultralytics 升级后 `DetectionLoss` 返回 0 维标量,cat 会崩。**在 pinned 版本 8.4.60 上确认 `base.ndim≥1`,并加一行断言**(你的冒烟通过说明当前版本 OK,但这是版本敏感点);
2. **BN 统计混用**:同一 forward 里 clean+fog 拼成 [2B] 一起过 backbone,BatchNorm 的 batch 统计同时吸收两种域——通常无害,但消融对比时(基线 vs L_feat)训练协议必须逐项一致;
3. **建议新增一个"数据路径冒烟"**:在 selftest 里再加一段——落一个小型 on-disk 配对数据集(2-3 张图),`build() → trainer.get_dataloader()` 拉一个 batch,断言 batch 含 `n_clean` 且 `L_feat>0`。**这一条能拦住缺口一/二/三这类问题,是上 GPU 前最有价值的自检**;
4. `PairedFogDataset.__getitem__` 的 `img_root` 拼接:`pairs.csv` 里 `clean`/`fog` 是相对路径,需要确认与 `img_root` 的目录层级一致(A3-01 输出在 `data/paired/` 下,见 P1-10 文档)。
