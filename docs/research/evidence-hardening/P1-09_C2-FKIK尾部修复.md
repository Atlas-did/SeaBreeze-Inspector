# P1-09 · C2 FK/IK 尾部修复 —— 把「P50 漂亮、P95 灾难」变成一个可控、可解释的工作空间结论

> 对应计划:`SeaBreeze_攻坚计划_v1.md` P1-9 · 证据脚本 `research/专项/C2/fk_ik_check.py`
> 一句话结论:**FK/IK 的自洽验证「P50=2.7e-10 mm」很漂亮,但 P95=123 mm、ikfk 关节残差 P95=3465° 说明尾部有系统性灾难——而且我已定位到根因:误差几乎全部来自 θ3→0°(手腕完全伸直)的位形,此时平面子雅可比秩亏,阻尼最小二乘在零空间里漂移**。这不是随机数值抖动,是一个物理可解释的现象:机械臂的 IK 在工作空间边界(最大伸程)处本质退化。修法:① 用「平面 2×2 雅可比」判退化(全 3×3 条件数查不出来);② 指标从「关节误差」改为「位姿误差」;③ 论文把尾部如实报成「奇异/边界邻域」并给出可用工作空间占比。

| 报告 | fkik P50=2.7e-10 mm,但 P95=123 mm;ikfk 关节 P95=3465°;雅可比 cond max=2.2e5 | 奇异邻域单独统计,排除后典型位形 P95 压到可解释量级;退化区域占比明确 |

**为什么值得做**:机械臂精度是评审硬指标(≤±10mm,8 分)。当前报告如果被审稿人看到「P95=123mm」,要么被认为脚本有 bug,要么被认为算法不可靠——**两种解读都对你不利**。但根因一旦讲清楚(伸直位形退化 + 边界分支),同一组数据就变成**正向的工程结论**:算法在典型位形下数值自洽(1e-9 量级),退化只发生在物理上本就该避免的伸直/边界位形,这恰恰为「IK 使用时应避开的工作空间」给出了量化边界。同一份报告,口径对了价值完全反转。

## 2. 问题定位(实测)

### 2.1 报告数字(`reports/fk_ik_report.json`,N=20000)

```
fkik_pos_err_mm:   p50=2.74e-10   p95=123.5   p99=128.2
ikfk_joint_err_deg: p50=1.10e-06  p95=3465.7
jacobian_cond:     p50=5.2  p95=61.1  p99=314.3  max=219974
```

### 2.2 我的诊断(N=50000 重跑 + 定位,可复现)

```
总样本=50000, 位姿误差>1mm 的占 5.22%
最差 8 例的 θ3 全部 ∈ [0.2°, 1.1°]   ← 手腕接近完全伸直
最差例: q=[5.6°, 149.2°, 0.2°], 末端 (-115.5, -11.2, 69.0)mm, 误差 164.6mm
这些失败位形的 3×3 雅可比条件数中位只有 2.6、P95=25 —— 比全体还低!
全体位形 3×3 cond: P50=5.1, P95=60, max=3.4e6
```

两个关键事实:

1. **尾部 = θ3→0° 的伸直位形**。θ3=0 时,平面(θ2,θ3)子雅可比的两列
   `[-L1 sin t2 − L23 sin(t2+t3), −L23 sin(t2+t3)]` 与 `[L1 cos t2 + L23 cos(t2+t3), L23 cos(t2+t3)]`
   在 t3=0 时严格平行(比例恒为 L23/(L1+L23))→ **平面子矩阵秩 1**,IK 的 θ2/θ3 沿零空间自由漂移,阻尼最小二乘在零空间里走到哪算哪。
2. **全 3×3 条件数查不出这个退化**(那些失败例子的 cond 反而低)——因为 t1 那一行还是满秩的,3×3 的奇异值被 t1 撑住了。所以**「加 cond>阈值 就过滤」是错的**,必须用平面子矩阵或直接判 θ3 接近 0 / 末端接近最大伸程。

另外,`ikfk_joint_err` 这个指标本身有设计问题:
- 它比的是 `q2` 与 `q_gt` 的**关节差**,而 3-DOF 臂的 IK 存在**合法分支切换**(t1 的 ±180° 等价、θ2/θ3 镜像解),一个完全正确的替代解会显示为巨大的「关节误差」;
- `err_ikfk.append(np.degrees(np.radians(q2 - q_gt)).max() ...)` 里 `degrees(radians(x))` 是恒等变换(死代码),对 3465° 这种量级说明求解器在某些位形下**根本没有收敛到任何分支**,而是在解空间里漂移后停在某处。

## 3. 改造方案

### 3.1 退化检测:用平面 2×2 雅可比,别用全 3×3

```python
def planar_cond(q):
    t2, t3 = np.radians(q[1:3])
    J2 = np.array([[-L1*np.sin(t2) - L23*np.sin(t2+t3), -L23*np.sin(t2+t3)],
                   [L1*np.cos(t2) + L23*np.cos(t2+t3), L23*np.cos(t2+t3)]])
    return float(np.linalg.cond(J2))
```

- 判定阈值建议 `κ2 > 50`(与全体 P95≈60 对齐)或按物理:`|r| 接近最大伸程 L1+L2+L3=135mm`(即 θ3≈0 附近)直接标记为边界位形;
- 报告分成两组统计:**典型位形**(κ2 ≤ 阈值)与 **退化/边界邻域**(κ2 > 阈值),分别报 P50/P95/P99,并给退化占比。

### 3.2 指标改为位姿误差 + 分支规范化

- `ikfk` 指标从「关节差」改成「**位姿差** `|FK(q2) − p_target|`」(与 fkik 一致),这才是 IK 真正关心的东西;
- 若仍想报关节差(说明分支选择稳定性),先把 q2 规范到 q_gt 的等价分支域(如 t1 取模 360、t2/t3 做镜像映射),再比;
- 顺带删掉 `np.degrees(np.radians(...))` 死代码。

### 3.3 新增「可用工作空间」指标(论文正向卖点)

- 用**中性初值**(不是真值作初值)重跑 IK,统计「在随机位形中,IK 在 N 步内收敛且位姿误差 < 1mm 的比例」;
- 输出:**可用工作空间占比**(如 94.x%),以及退化边界的三维描述(θ3≈0 的曲面 = 最大伸程球面);
- 论文可以写:「机械臂在典型工作空间内 FK/IK 数值自洽(<1e-9 m,P50),退化邻域(θ3→0,末端处于最大伸程)占采样空间的约 5%,IK 在该区域内解不唯一,实际控制应避开」。

### 3.4 可选:改进求解器对边界的处理

- 在 `ik()` 里加**解质量检查**:平面子 Jacobian 奇异时,改走解析 IK(2-DOF 平面臂的解析解),或对该区域直接返回「不可达」标记而不是硬算;
- 这对**真机控制**有用(避免机械臂在边界抖动),但对「验证脚本」不是必须——先做到 3.1–3.3,让报告可信。
