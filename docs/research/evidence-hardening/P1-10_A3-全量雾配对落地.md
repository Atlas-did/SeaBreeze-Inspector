## 2. 澄清与定位

### 2.1 代码现状(仓库 w1 与证据包一致)

`clean_and_visibility.py`:
- L54 `ap.add_argument('--max', type=int, default=None, help='最多处理前 N 张(默认全部)')`;
- L60-61 `if a.max is not None: imgs = imgs[:a.max]`;
- 输出 `sharpness.csv`(每图拉普拉斯方差)+ `pairs.csv`(clean, fog, beta, type, invisible_flag)。

所以**脚本层面没有硬编码 200**。两种可能:(a) GAP_TRACKER 写自更早版本;(b) 你本地的实际运行命令带了 `--max 200` 或用了旧副本。建议:以仓库这份为准,若你机器上的副本还是写死 200,用仓库版本替换。

### 2.2 规模与预算(跑全量前必须先算)

clean 池 = `clean_manifest.csv` 的 **7001 个唯一内容**(train 4900 / val 1050 / test 1051)。按 A3-01 默认 `--betas 0.5,1.0,1.5,2.0`:

| 项 | 估算 |
|---|---|
| 输出图数 | 7001 × 4 = **28004 张雾变体**(+ sharpness 的 7001 行) |
| 单图体积 | 1024×1024 PNG 约 1–2 MB;1280 约 2–3 MB |
| 磁盘需求 | 约 **30–70 GB**(PNG 无损压缩,取决于图内容) |
| 生成耗时 | Laplacian + 雾合成约 0.1–0.3 s/图(单核);串行约 1–2 h,4 核并行约 20–40 min |
| 内存 | 逐图处理,峰值 <200 MB,无压力 |

**结论:磁盘是唯一硬约束**(30–70 GB)。跑之前先确认 `df -h` 有余量;不够就降 `--betas`(先 2 档)或降分辨率(与训练 imgsz 对齐即可,不必 1280)。

### 2.3 一个必须现在定的口径:雾变体的 split 归属

- 用 train 的 clean 生成训练雾变体、val 生成验证、test 生成测试——**严禁跨 split**(否则又制造泄漏,和 v3 同一个坑);
- 每个雾变体的 sha256 记入 manifest,parent 图字段保留,三向零碰撞沿用 `clean_manifest.csv` 的审计方法;
- pairs.csv 里直接带 `split` 列,训练脚本(A3-02)按它划 DataLoader。

## 3. 执行方案

### 3.1 前置核对(5 分钟)
- 确认 `clean_manifest.csv` 的三向零碰撞属性随数据一起拷贝(该文件在数据集清单包里,需随 clean 图放到 `data/` 下);
- 确认 clean 图所在目录与 labels 目录路径(labels 是 A3-01 计算 invisible_flag 的输入,缺标签的图会标 invisible=0,需留意统计口径)。

### 3.2 本机代跑(我可以做)
1. 在 scratch 目录搭好数据软链(clean 图 7001 张 + 标签);
2. 先小样验证:`--max 50` 跑一遍,核对输出结构、invisible_flag 分布、图能正常打开;
3. 全量跑:`--images <clean池> --labels <labels> --out data/paired/ --min-sharpness 50 --betas 0.5,1.0,1.5,2.0`(不带 `--max`);
4. 审计:① 输出图数 = clean 数 × 4;② 抽查 20 张雾变体肉眼确认(这一步需要你,因为我看不了图);③ invisible_flag 按 β 分档统计占比(浓雾下不可见样本比例应该随 β 上升,这是预期趋势,也是论文「invisible 样本处理」实验的数据基础)。

### 3.3 落库
- `data/paired/` + `pairs.csv` + 雾变体 manifest 一并整理进数据集(交付物四件套之一);
- GAP_TRACKER 的「只跑了 200 张」条目更新为「全量 28004 配对,manifest 三向零碰撞」。
