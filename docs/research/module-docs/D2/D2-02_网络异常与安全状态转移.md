# D2-02 通信链路异常与安全状态转移：故障注入与降级策略

> 本模块第二篇。**链路（图传/数传/遥控）丢失、丢包、延迟抖动是无人机运行的常态性风险。本文定义故障注入协议（丢包率、延迟抖动、断链时长），设计安全状态机（正常→降级→安全保持→紧急），并验证每种状态下系统行为符合预期。**
> 证据层 L2（故障注入台架）+ L3（仿真）。

## 〇、前置判断

"断链就返航"是空话；断链时到底切到哪个状态、保留什么能力、怎样恢复，需要逐级定义并实测。且故障注入必须是**可复现的**（注入器在数据链路层做，不改应用逻辑），否则"测试了断链"无法复核。本文把链路异常当一类可测试的输入来对待。

## 一、问题严格定义

- 链路异常类别：完全断链（t>阈值的无包）、丢包率 $$r_{loss}$$、延迟抖动 $$\sigma_{lat}$$、乱序。
- 系统状态机（示意）：
  - **NORMAL**：全链路健康；
  - **DEGRADED**：丢包/延迟超阈值，降级感知（降低帧率/降采样/改用本地处理），保留任务；
  - **HOLD/SAFE**：严重链路恶化，进入安全保持（悬停/本地缓存，不执行危险动作）；
  - **EMERGENCY**：断链超时，触发应急（限速降落/返航等，按应用定义）。
- 目标：为每条转移定义触发条件（阈值）+ 动作 + 恢复条件，并在注入实验下验证状态转移正确、无振荡、无危险行为。
- 边界：安全状态机的"安全动作"取决于应用场景（巡检/物流/侦察不同），本文定义框架与验证协议，具体动作由应用配置。

## 二、该做什么

1. 在数据链路层做故障注入器：`loss %`、`jitter ms`、`blackout s` 可配置，可编程触发（按时间/按事件）。
2. 实现状态机：状态、转移条件（阈值）、动作表、恢复条件；状态切换打日志。
3. 注入实验矩阵：断链时长 {0.5s, 2s, 10s}、丢包 {10%, 50%, 90%}、抖动 {10ms, 100ms} 交叉，每格 N≥20 次。
4. 验证：状态转移序列符合预期、无振荡（短时恢复又断的抖动）、无危险动作（注入后没有进入未定义状态）。
5. 恢复验证：链路恢复后，系统正确回到 NORMAL/DEGRADED 且状态机不卡死。

## 三、技术方案（要点）

- 注入器：`tc netem` 或用户态代理（丢包/乱序/延迟），在协议栈层注入；日志记录注入窗口与真实到达包数，保证"注入强度可核对"。
- 状态机判定：用滑动窗口统计（如最近 1s 的丢包率）而非瞬时值，避免单包抖动误触发。
- 恢复逻辑：链路恢复后需稳定 N 个连续心跳才切回（去抖），防止振荡。
- 每状态定义"允许动作集"：DEGRADED 禁止什么、SAFE 保留什么——写进配置表，注入实验逐项核对。

## 四、数据层

- 数据来源：本项目台架 + 仿真。`d2_fault_inject.csv`（注入窗口、真实丢包率、状态序列、动作日志）。
- 参考规范（仅作对照）：检索无人机安全标准/链路指标（如 AOPA/民航局无人机相关规范、厂商链路 spec）——记录 URL 与版本，写入 `data_sources.csv`；**不**以"符合某规范"为结论除非逐条核对。

## 五、可能踩的坑

1. **注入器与应用耦合**：注入在应用层改代码，测试的不是链路而是改过的代码。注入必须发生在链路层/网络层。
2. **状态机振荡**：恢复阈值设得太紧，链路抖动下 NORMAL↔DEGRADED 来回跳。加去抖与滞回。
3. **单包瞬时误判**：用瞬时丢包率判转移，一个突刺就降级。用滑动窗口统计。
4. **注入强度不可核对**：没记录真实丢包/延迟，测试结果无法归因。注入日志必须与接收端统计对得上。
5. **未定义状态**：异常组合（如断链+电机饱和）可能进未定义分支。状态机穷举表 + 注入矩阵覆盖。
6. **恢复不验证**：只测"掉链时进 SAFE"，不测"恢复后回来"——恢复路径没测等于没测完。
7. **把"进入安全状态"当"安全"**：安全保持若仍执行任务动作，可能造成危险。动作集核对是必须的。

## 六、评估指标与消融设计

- 输出：注入矩阵 × 状态转移正确率、振荡次数、未定义状态次数、恢复成功率。
- 消融：去抖窗口长度、恢复确认包数、状态机版本（有/无滞回）——验证设计决策。
- 指标：`转移正确率`、`平均转移延迟`、`振荡率`、`恢复时间`。

## 七、论文写法

可写：

> 通过链路层故障注入（断链≤10s、丢包≤90%、抖动≤100ms）验证状态机：所有注入下系统进入预期安全状态，无振荡与未定义状态，平均恢复时间 …。

禁写：`系统完全可靠`（只测了定义范围内的注入）、`符合 XX 安全标准`（未逐条核对）、`断链安全`（未定义"安全动作"边界）。

## 八、诚实自评锚点

- **可交付**：注入器 + 状态机 + 注入矩阵 + 转移/恢复统计。
- **部分完成**：只测了丢包未测断链 → 标注范围，论文写"丢包与抖动范围"。
- **不可声称**：超出注入范围的可靠性、外部标准符合性、真实链路等价性（注入≠真实电磁/距离效应）。
- **停止线**：注入强度不可核对、或未定义状态可触发时，停止安全结论。
