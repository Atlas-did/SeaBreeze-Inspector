# D2-01 系统闭环时延分解：t0–t3 逐段测量与预算分配

> 本模块第一篇。**"系统时延"不是单个数字：采集→预处理→感知→决策→执行各有各的延迟，对稳定闭环（B1 抗风）与感知-执行链，预算必须逐段量化。本文给出 t0–t3 分解协议、测量方法、以及"哪些段可优化、哪些是硬边界"。**
> 证据层 L2（台架/实机实测）。

## 〇、前置判断

无人机闭环的时延若只看"端到端"，看不出瓶颈在哪；但逐段测也有陷阱——各段时钟不同步、缓存/队列抖动、数据源耦合。本文的目标：定义清晰的时间戳边界，在**同一基准时钟**下测量，给出 P50/P95/P99 与各段占比，并指出**时延不可压缩的下限**（曝光、传输、执行器响应是物理下限）。

## 一、问题严格定义

- 链路：`相机曝光(t0) → 读出/传输 → 预处理 → 感知模型推理 → 决策 → 执行指令 → 舵机/电机响应完成(t3)`。
- 分段（相邻段之间插入时间戳）：
  - $$\Delta_{sensor}$$：t0→图像可用（曝光+读出+传输）；
  - $$\Delta_{pre}$$：预处理（去畸变、缩放、格式转换）；
  - $$\Delta_{percep}$$：感知推理（模型前向，可含 SAHI/超分等推理侧组件）；
  - $$\Delta_{decis}$$：决策（控制律/规划，含调度与排队）；
  - $$\Delta_{act}$$：执行指令到舵机/电机到达目标（含通信、PWM、机械响应）。
- 端到端：$$\Delta_{tot}=t_3-t_0=\sum\Delta_i$$ + 各段间排队抖动。
- 稳定边界（与 B1 结合）：在风扰下，闭环相位裕度要求 $$\Delta_{tot}\cdot f_{bw}\ll 1$$，即总时延低于控制带宽倒数的某个分数。

## 二、该做什么

1. 定义每个时间戳的物理意义与测量点（代码插桩 / 硬件信号 / 相机时间戳）。
2. 同一时钟：用单调时钟同步所有插桩点（或记相对偏移），避免各段时钟漂移。
3. 测量协议：≥1000 次运行，记录各段与端到端，出 P50/P95/P99、直方图、各段占比。
4. 分别测：稳态（无负载）与满载（感知并发 + 控制循环）。
5. 输出预算表：每段 `值 | 可优化? | 优化手段 | 硬边界(物理下限)`。

## 三、技术方案（要点）

- 插桩示例：时间戳用 `time.perf_counter_ns()`（用户态），首尾对齐；相机用硬件时间戳（若有）。
- 感知推理延迟单独测：纯推理（无 I/O）、含预处理、含后处理——分开，便于与 A3/A4 的推理侧组件（SAHI 切片、超分）对齐。
- 排队抖动：任务调度器把感知/控制插在同一个线程时，抖动可能超过均值——报告 P95/P99 而非只报均值。
- 执行段：PWM 生成到机械到位需另测（C1 台架），电子时延与机械时延分开。

## 四、数据层

- 数据来源：本项目实机/台架插桩采集；`d2_latency_raw.csv`（run_id、t0..t3、各段 ns、工况标记）。
- 参考量级（仅作对照，不引用为结论）：检索无人机感知-控制时延文献/厂商指标（如 DJI 云台控制周期、ROS2 通信延迟 benchmark）——记录 URL 与版本，写入 `data_sources.csv`。

## 五、可能踩的坑

1. **时钟不同步**：各段用自己的时钟（或时间戳来自不同源），累加时系统性偏大/偏小。统一基准。
2. **只报均值**：实时系统看 P99；均值好但 P99 差 = 偶尔抽风，稳定性不可接受。P50/P95/P99 全报。
3. **缓存与队列没算**：感知结果排队等决策、决策排队等执行——这两段最容易漏。
4. **测量插桩本身影响结果**：插桩点开日志 I/O 会加延迟。测完用轻量采样（profiling）校验。
5. **把"推理延迟"当"系统时延"**：论文里若只报 GPU 前向 ms，忽略了传输/调度/执行，是低估。端到端必须全链。
6. **忽略负载耦合**：感知和控制在同核上跑时，满载延迟可以差 2–3 倍。稳态与满载分报。
7. **执行段用规格书数字**：舵机标称"0.1s/60°"是空载；实际负载下机械响应差异大。用 C1 实测。

## 六、评估指标与消融设计

- 主表：各段与端到端的 P50/P95/P99、占比、抖动（IQR）。
- 消融：满载 vs 稳态；感知侧组件开关（SAHI 开/关、超分开/关）对 $$\Delta_{percep}$$ 的影响；调度策略（单线程/多线程/优先级）。
- 稳定预算校验：把实测 $$\Delta_{tot}$$ 代入 B1 闭环模型，算相位裕度——"时延是否吃掉了稳定裕度"。

## 七、论文写法

可写：

> 系统端到端时延 P95 为 X ms，其中感知推理占 Y%（Z ms）、执行响应占 …；满载下 P99 增至 …，对 B1 控制带宽（f_bw=…Hz）的相位裕度影响为 …，仍在/超过预算。

禁写：`端到端时延为 X ms`（无 P95/P99 与工况）、`时延满足实时要求`（无控制带宽校验）、只报 GPU 前向当系统时延。

## 八、诚实自评锚点

- **可交付**：插桩协议 + 原始数据 + 预算表 + 稳定裕度校验。
- **部分完成**：只测了稳态 → 满载与负载耦合单列，论文标注适用范围。
- **不可声称**：跨平台时延（不同硬件差异大）、实时性（无调度器时序保证/硬实时证据）。
- **停止线**：时钟未同步、或 P99 未报时，停止时延结论。
