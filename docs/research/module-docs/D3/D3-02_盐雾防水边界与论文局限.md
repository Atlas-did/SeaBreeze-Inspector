# D3-02 盐雾 / 防水边界与论文局限声明：视觉抗雾 ≠ 硬件耐盐

> 本模块第二篇（收尾）。**最重要的边界：本文解决"感知层的抗雾"，与"硬件的盐雾防护/IP 防水"是两个不同的问题。本文明确列出：哪些是视觉层证据，哪些尚未有硬件证据，以及论文局限如何写才不会误导读者。**
> 证据层：本模块为综述/边界声明，引用 L1–L4 各层证据。

## 〇、前置判断

读者最容易被误导的地方：**模型在合成雾上 mAP 提升** → 被理解为"无人机能在海上盐雾环境稳定工作"。后者还依赖硬件（镜头盐晶附着、PCB 防护、金属腐蚀、风机盐蚀）、电源与散热、以及长期可靠性。本文的角色是把边界划清楚：视觉抗雾论文的结论范围到哪、硬件验证还缺什么、局限怎么措辞。

## 一、问题严格定义

- 两条独立能力链：
  - **感知链**：雾/盐雾对图像的影响 → 模型鲁棒性（A3 系列已做）；
  - **硬件链**：盐雾对镜头/机身/电子/执行器的影响 → 长时间可靠性（本模块声明边界，不实测）。
- 明确区分：**视觉抗雾（感知）** vs **硬件耐盐（环境可靠性）** vs **IP 防水（外壳防护等级）**。
- 论文局限清单：哪些结论可声明、哪些只能在局限性中列出待验证。

## 二、该做什么

1. 整理已证实的感知层结论（A1–D2 各模块可声明的数字）。
2. 列出硬件链缺口：镜头盐晶附着（光学）、PCB/连接器（电学）、金属结构（腐蚀）、执行器（C2 工业清单）——每项写"需要什么测试"。
3. 检索 IP 防水/盐雾测试标准（如 IEC 60529 IP 等级、盐雾试验 ISO 9227）——记录来源，说明我们的设备**未**做这些标准测试（除非真做了）。
4. 写局限声明模板：`本工作在感知层验证抗雾；硬件盐雾防护与长时间海上可靠性未验证，需……`。
5. 向用户/团队交付"哪些话能写进论文、哪些话不能"的清单。

## 三、技术方案（要点）

- 无实测方案：本模块是**边界声明**而非实验。它引用其他模块的证据（A3 合成雾、C1 舵机、D2 时延），并补充硬件缺口的明确列表。
- 若团队后续要做硬件验证，给出入口：盐雾试验箱、IP 测试、镜头防雾镀膜与防雨罩、腐蚀防护涂层；列成本与周期量级（检索供应商/标准）。
- 措辞纪律：`抗雾（视觉）` vs `耐盐（硬件）` 在全文必须一致，不混用。

## 四、数据层

- 输入：各模块已交付数据（A3 pairs.csv、C1 c1_raw.csv、D2 时延等）。
- 参考来源：IEC 60529、ISO 9227、IP 等级定义、镜头防护材料规格——逐条记录 URL/版本，写入 `data_sources.csv`。

## 五、可能踩的坑

1. **混用"抗雾"与"耐盐"**：读者/评审最容易掉进的语言陷阱。全文术语纪律化。
2. **用合成雾数据写硬件结论**：模型在合成雾上提升 ≠ 镜头在盐雾下不结晶。边界必须写。
3. **IP 等级被误用**：说"IP65"意味着通过标准测试；未测就写是造假。不测就不写。
4. **局限声明太软**：`"有待进一步研究"` 没有具体缺口列表 = 没有信息量。每条局限配"需要什么数据/实验"。
5. **把实验室台架当海上实测**：Tello 台架与海上工业无人机环境差量级。证据层标注不可省。
6. **忽略长期可靠性**：腐蚀/盐晶是累积效应，短期演示测不出。局限里写"长期可靠性未覆盖"。
7. **在结论章节突然宣称"海上可用"**：结论只能复述已验证范围，不能夹带硬件假设。

## 六、评估指标与消融设计

- 输出：论文"可声明结论清单"与"局限清单"对照表（每条带证据来源）。
- 术语核查：全文扫描"抗雾/耐盐/防水/海上可用"用词，标出越界处。
- 边界矩阵：`能力 | 已验证证据 | 未验证证据 | 需要的测试`。

## 七、论文写法

可写：

> 本工作在感知层验证了合成海雾与运动模糊下的鲁棒性（L3 证据）；硬件盐雾防护、IP 防护与长时间海上可靠性不在本文范围，需盐雾试验（ISO 9227）、IP 测试与现场长期试验验证。

禁写：`海上长期稳定运行`、`满足 IP 防护要求`（未测）、`抗雾=耐盐` 的任何等价表述。

## 八、诚实自评锚点

- **可交付**：边界声明 + 术语纪律 + 局限模板 + 可声明结论清单。
- **部分完成**：只做了声明 → 这就是本模块的交付；若要硬件验证需立项另测。
- **不可声称**：任何硬件可靠性、任何标准符合性（未测）。
- **停止线**：若团队坚持写"海上可用"，本模块立场不变：先做盐雾试验。
