# B3-02 绝对定位证据链与论文边界

> 本模块第二篇。明确绝对定位需要什么真值系统；真值缺失时把结论降级为"相对状态辅助"，并给出可执行的取证路径。
> 前置：B3-01 测量链路。证据层 L2/L4。

## 〇、前置判断

Tello 的光流/气压只提供**相对状态辅助**，不是绝对定位。工业平台需要 RTK/视觉-惯导/动捕/激光等外部真值。当前仓库无 RTK 栈，论文里任何"绝对定位"表述必须删掉或标为设计目标。

## 一、问题严格定义

- 绝对定位误差：估计位置与外部真值（RTK 厘米级、动捕、激光跟踪）的偏差统计。
- 当前可用：光流/气压 → 短时相对运动；无外部真值 → 无绝对误差可测。
- 输出：真值系统需求清单 + 若具备时的测量协议 + 缺失时的诚实表述。

## 二、该做什么

1. 列真值选项：RTK 基站+流动站、室内动捕、激光跟踪（精度/成本/室外可用性）。
2. 若选室内模拟：动捕/UWB 覆盖、标定、刷新率。
3. 若选 RTK：基站架设、流动站与飞控连接（工业平台接口；Tello 无 RTK）、已知坐标点验证。
4. 当前阶段：输出需求清单与"待提供"标记，不硬造绝对数字。

## 三、技术方案

- 若真值可用：真值与遥测时间对齐（PTP/NTP/共享时钟），$$e(t)=\|\hat p(t)-p_{gt}(t)\|$$ 的 RMSE/p95/CI。
- 真值缺失表述模板见第七节。
- 弱 GNSS 故障注入属 D3-01；本方案聚焦真值系统。

## 四、数据层

- `gt_system.yaml`：类型、型号、标定文件、时间同步方式、已验证精度。
- 与遥测的时间戳对齐是硬性字段。

## 五、可能踩的坑

1. 把光流积分当绝对位置（漂移累积）。
2. RTK 实测精度比宣称低（多路径/遮挡/距离）→ 必须用已知点验证。
3. 时间不同步 → 位置误差混入时延误差。
4. 仿真 GNSS 说成实测。
5. 论文写"视觉里程计已实现"（仓库没有 VIO）。

## 六、评估指标与消融设计

- 有真值：绝对位置 RMSE/p95 + 时间对齐验证 + CI。
- 无真值：需求清单 + 声明"绝对定位精度未在当前平台评估"。

## 七、论文写法

可写：`当前验证平台缺少 RTK/外部真值，绝对定位精度未评估；工业平台需采用 RTK 与视觉-惯导等冗余定位方案。`

禁写：`±5 cm 绝对定位`、`视觉里程计已实现`、`厘米级导航`。

## 八、诚实自评锚点

- **可交付**：真值需求清单 + 若有真值的测量协议。
- **部分完成**：真值缺失 → 绝对定位只作局限性与未来工作。
- **不可声称**：任何绝对定位数字、VIO 已实现。
- **停止线**：没有真值系统时任何绝对定位表述不进论文。
