# v5_scene_yolo11s_1024 失败分析与改进报告

**报告日期：** 2026-08-20  
**实验名称：** `v5_scene_yolo11s_1024`  
**结论性质：** 基于数据集审计、训练参数、71 个完整 epoch 的 `results.csv`、权重文件和训练批次可视化得出；工作文档中的描述仅作背景，不作为实验结论。

---

## 1. 执行摘要

本次实验不是 GPU、CUDA、路径或标签格式故障，而是一次**能够正常训练、但验证泛化失败**的实验。

模型在训练集上的损失持续下降，但在按连续场景隔离后的验证集上几乎不能正确检测缺陷。71 个完整 epoch 中，最佳结果出现在第 68 轮：

| Precision | Recall | mAP50 | mAP50-95 |
|---:|---:|---:|---:|
| 0.1890 | 0.03252 | 0.02661 | 0.01319 |

第 70、71 轮的 mAP50 又分别回落到 0.00770 和 0.00555，说明第 68 轮只是小幅波动，没有形成稳定上升趋势。因此在第 72 轮人工中断是正确决定。

失败原因按影响程度排序如下：

1. **主要原因：训练集与验证集的场景域差异过大。** v5 将连续航拍段整体隔离后，验证集主要由训练阶段未覆盖的拍摄距离、叶片尺度和背景构成。
2. **场景块划分过于粗。** 验证集只有 2 个大场景块，其中一个场景提供了 100/123 个验证框，单个域对总指标影响过大。
3. **训练集负样本占比过高。** 2140 张训练图中有 1731 张无缺陷框，占 80.89%，平均一个 batch 很容易没有正实例。
4. **增强策略不适合稀疏小目标。** 原实验使用 `mosaic=1.0`、`scale=0.5`，会继续缩小本来已经较小的缺陷。
5. **目标数量少且尺度偏小。** 训练集只有 409 张正样本、546 个唯一框，跨场景学习难度高。

这些问题共同造成模型倾向于输出“没有缺陷”，表现为 Recall 极低。换成 YOLO11m 只会增加容量，不能解决数据域和采样问题，因此不应直接换大模型重跑。

## 3. 数据集变化与审计结果

### 3.1 v4 原始划分

| split | 图片 | 有缺陷图片 | 无目标图片 | 框 | 父图 |
|---|---:|---:|---:|---:|---:|
| train | 2120 | 423 | 1697 | 559 | 212 |
| val | 440 | 82 | 358 | 113 | 44 |
| test | 480 | 82 | 398 | 109 | 48 |

v4 没有 SHA-256 完全重复图片，也没有同一个父图 ID 跨集合，但存在明显的连续场景相似性：

- 连号父图对共 277 对，其中 139 对跨 train/val/test，占 50.18%；
- val/test 中，与 train 同位置瓦片的最近图像 pHash 距离不超过 4/8/12 的分别有 48/126/230 张；
- 存在 12 个短边小于 4 px 的切片边缘残框。

这意味着 v4 评估中，训练集可能见过与验证/测试图极其相似的前后航拍帧。v4 的成绩并非“代码造假”，但它更多衡量**同场景附近帧泛化**，不能直接代表对新航拍场景的泛化。

### 3.2 v5 保守场景隔离划分

| split | 图片 | 有缺陷图片 | 无目标图片 | 框 | 父图 |
|---|---:|---:|---:|---:|---:|
| train | 2140 | 409 | 1731 | 546 | 214 |
| val | 430 | 89 | 341 | 123 | 43 |
| test | 470 | 80 | 390 | 100 | 47 |

v5 的改动包括：

- 连续 DJI 编号场景块整体分配到同一 split；
- 连号父图跨 split 从 139 对降到 0 对；
- pHash 距离不超过 4/8/12 的 val/test 图片从 48/126/230 张降到 1/7/32 张；
- 删除了 12 个短边小于 4 px 的边缘残框；
- 图片未重新编码，标签结构错误为 0。

这套划分显著降低了相邻帧泄漏，但也改变了问题难度：v4 与 v5 不再是在同一种验证条件下比较。

### 3.3 验证集被单一场景主导

v5 验证集只包含两个大场景块：

| 验证场景 | 图片 | 有缺陷图片 | 框 | 验证框占比 |
|---|---:|---:|---:|---:|
| DJI_0234–0251 | 140 | 22 | 23 | 18.70% |
| DJI_0685–0713 | 290 | 67 | 100 | 81.30% |

其中 DJI_0685–0713 包含大量近距离、灰色天空背景、叶片占画面比例很大的视角，与训练集常见的绿色地面背景和斜向叶片视角差异明显。由于该场景贡献了 81.30% 的验证框，模型只要不能适应这个域，总体 mAP 就会接近 0。

当前 v5 因而更接近一次**未见场景压力测试（OOD test）**，而不是普通的同分布验证。

|---:|---:|---:|---:|---:|

v4 在第 77 轮达到 mAP50=0.43491，最终最佳权重在原 v4 验证集上约为：

- Precision：0.79367；
- Recall：0.61947；
- mAP50：0.66790；
- mAP50-95：0.34781。

但 v4 与 v5 的数据划分难度不同，不能把 0.66790 与 0.02661 简单解释为“新代码退化了 25 倍”。更准确的解释是：**旧评估包含相邻场景相似性，新评估要求跨场景泛化，暴露了模型此前没有解决的问题。**

严格来说，在第 72 轮停止不能从数学上证明模型跑到第 200 轮也绝无改善；但截至第 71 轮，最高 mAP50 仅 0.02661 且不能保持，验证损失差距没有收窄，而 v4 同期已经达到 0.25934。因此本次应定义为“未通过第一阶段门槛”，在有限 GPU 配额下继续跑满 200 轮的收益预期很低。

### 4.3 最有力的泛化差距证据

第 71 轮时：

| 指标 | v4 | v5 |
|---|---:|---:|
| train box loss | 2.2111 | 2.1786 |
| train cls loss | 2.6044 | 2.4190 |
| val box loss | 2.3654 | 2.9332 |
| val cls loss | 2.6468 | 5.2202 |

v5 的训练损失并不比 v4 差，甚至略低，但 v5 的验证分类损失约为 v4 的 1.97 倍。这说明模型已经能够拟合 v5 训练场景，却无法把学到的判别规则迁移到验证场景。该证据支持“场景域差异是主因”，而不是“训练程序没有工作”。

## 5. 训练集无目标图片比例的影响

“无目标图片”指图片有效、对应标签文件也存在，但标签内容为空，即该图没有标注缺陷框。它不是空白图，也不等同于文件损坏。

v5 训练集：

- 唯一训练图片：2140；
- 有缺陷图片：409；
- 无目标图片：1731；
- 无目标图片占比：80.89%；
- 无目标/有缺陷图片比例：4.232:1。

若近似按独立均匀采样计算，一个 batch=8 全部由无目标图片组成的概率为：

```text
(1731 / 2140)^8 = 18.33%
```

这与日志中多次出现 `Instances 0` 一致。负样本并非越少越好，它们能够抑制草地、叶片纹理和风机结构误报；但比例过高时，模型会频繁获得“不要输出框”的训练信号，容易形成低 Recall。

因此正确做法不是删除全部负样本，而是仅在训练采样阶段提高正样本出现频率，同时保持 val/test 的真实比例。

## 6. Mosaic 与小目标问题

数据集在 1024×1024 图像上的缺陷框具有以下特征：

- 短边中位数约 44 px；
- 仍有 50 个框短边小于 16 px；
- 82 个框接触切片边界；
- 每张正样本平均约 1.34 个框，目标非常稀疏。

失败实验使用 `mosaic=1.0` 和 `scale=0.5`。Mosaic 会把多张图拼接到同一训练画布，原本较小的缺陷可能再次缩小；较大的 scale 扰动还可能让小目标更难定位。在数据充足时这些增强通常有益，但对于当前稀疏小目标和高负样本比例，强度偏大。

这不是唯一根因，但会放大低 Recall 和定位不稳定。

## 7. 已排除的原因

### 7.1 不是 GPU 或 CUDA 故障

- `nvidia-smi` 正常识别 A10；
- `torch.cuda.is_available()` 为 True；
- 训练速度和显存占用稳定；
- 没有 OOM、NaN 或 CUDA kernel 错误。

### 7.2 不是数据路径错误

- 训练集、验证集均成功扫描；
- 验证日志稳定显示 430 张图片、123 个实例；
- 如果路径错误或图片无法读取，训练不会连续完成 71 个 epoch。

### 7.3 不是标签格式错误

- 审计中 YOLO 标签结构错误为 0；
- 训练集读取到 546 个唯一框；
- 训练批次图能够绘制 class 0 的真实框；
- 训练损失能够下降。

### 7.4 不是人工中断造成失败

人工中断发生在第 72 轮，而模型从第 1～71 轮已经长期保持极低 mAP。中断只是避免继续浪费 GPU 配额，不是低精度的原因。

### 7.5 不能用 v4 `best.pt` 直接验证 v5 划分

v4 权重训练时见过一部分后来被重新分到 v5 val/test 的图片。因此用 v4 `best.pt` 在 v5 val/test 上得到的高分仍带有训练集重叠，不能作为干净的跨场景基线，也不能用该权重续训 v5。

## 8. 为什么暂时不换 YOLO11m

YOLO11m 的参数更多，可能提高同分布拟合能力，但当前瓶颈是：

- 训练域缺少验证域代表性；
- 正负采样不平衡；
- 小目标增强强度不合适；
- 验证集被单一场景主导。

这些问题不会因模型变大自动消失。更大的模型还可能更快记住训练背景，使训练损失进一步降低，却不改善验证 mAP，并消耗更多 GPU 时间。

正确顺序是先让 YOLO11s 在修正版设置下通过短程门槛，再使用相同划分、seed 和输入尺寸比较 YOLO11m。

## 9. v5.1 已实施的修改

v5.1 补丁不移动图片、不删除负样本，也不修改 val/test，只改变训练采样清单和增强默认值。

### 9.1 正样本重复采样

| 项目 | v5 | v5.1 有效训练清单 |
|---|---:|---:|
| 唯一图片数 | 2140 | 2140（不变） |
| 正样本有效条目 | 409 | 866 |
| 负样本有效条目 | 1731 | 1731 |
| 总有效训练条目 | 2140 | 2597 |
| 负/正比例 | 4.232:1 | 1.999:1 |
| batch=8 全负概率 | 18.33% | 3.90% |

实现方式是让训练清单重复引用正样本路径，不复制图片文件：361 张正样本每轮出现 2 次，48 张正样本每轮出现 3 次。Ultralytics 8.4.123 的实际扫描结果为 2597 个条目、866 个正样本条目、1731 个背景条目，说明重复清单能够被正确加载。

### 9.2 降低增强强度

| 参数 | 失败实验 | v5.1 |
|---|---:|---:|
| mosaic | 1.0 | 0.2 |
| scale | 0.5 | 0.25 |
| translate | 0.1（默认） | 0.05 |
| mixup | 0 | 0 |
| cutmix | 0 | 0 |
| copy_paste | 0 | 0 |

目的不是取消所有增强，而是降低小缺陷被缩小或裁出画面的概率。

### 9.3 v5.1 的边界

v5.1 首先验证“采样不平衡与强 Mosaic 是否放大了失败”，但它没有把当前 OOD 验证场景混入训练集，也没有通过降低验证难度制造高分。如果 v5.1 在第 60 轮仍然低于门槛，则下一步应重做**场景分层划分**或建立“同分布验证 + 独立 OOD 测试”的双评估协议。

## 10. 下一轮实验方案与验收标准

### 10.1 第一阶段配置

```bash
python train_cli_v5_1.py \
  --data clean_binary_v5_scene_clean/data_v5_1.yaml \
  --model yolo11s.pt \
  --imgsz 1024 --batch 8 --epochs 80 --seed 0 \
  --project runs/detect --name v5_1_balanced_yolo11s_1024 \
  --device 0 --workers 8
```

必须从官方 `yolo11s.pt` 开始，不能使用 v4 或失败 v5 的 `best.pt` 续训。

### 10.2 中期门槛

| 检查点 | 判定 |
|---|---|
| 第 40 轮 mAP50 < 0.03 | 继续观察到第 60 轮，但不启动 YOLO11m |
| 第 60 轮 mAP50 < 0.05 | 停止；采样修复不足以解决场景域问题 |
| 第 60 轮 mAP50 ≥ 0.10 且趋势上升 | 跑完 80 轮 |
| Recall 长期 < 0.10 | 继续检查漏标、场景覆盖和目标尺度 |

不要根据单轮尖峰判断成功。至少需要连续若干轮 mAP 与 Recall 同时改善，并且验证损失不再持续远高于训练损失。

### 10.3 后续场景划分建议

若 v5.1 仍失败，建议建立两个口径：

1. **ID validation（同分布验证）：** 每种拍摄距离、背景、叶片尺度均在 train/val 中有独立场景块，同时设置相邻帧缓冲，禁止近重复跨集；用于模型选择和调参。
2. **OOD test（未见场景测试）：** 完整保留从未进入训练的航拍会话；只在最终模型确定后评估，用于报告真实跨场景泛化。

这种双口径能够同时避免 v4 的相邻帧虚高，也避免当前 v5 用两个场景块承担全部验证功能。

---

## 11. 最终结论

本次实验的价值不在于得到可部署权重，而在于确认了旧 v4 结果没有充分衡量跨场景泛化。清除连续帧泄漏后，YOLO11s 在训练集上能够下降损失，却无法适应验证集的拍摄域，最终最佳 mAP50 仅为 0.02661。

因此应把本次结果记录为：

> **失败类型：场景域泛化失败，伴随负样本采样过多和小目标增强过强；非环境、代码崩溃或标签解析失败。**

下一步先用 v5.1 的正样本重复采样与低 Mosaic 配置做 80 轮门槛实验。若第 60 轮仍低于 mAP50=0.05，则应停止继续堆模型，转向场景分层数据划分和双评估协议。
